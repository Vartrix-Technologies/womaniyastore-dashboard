# File Review: superadmin/page.tsx

## 1. File Responsibility

**Primary Purpose**: System monitoring dashboard for superadmin role to check health status, manage offline sync, test connections, and export/import database backups.

**Single Responsibility Assessment**: Moderate - handles both monitoring (read-only status checks) and administrative actions (sync, export). Could separate monitoring from backup operations, but grouping under "system admin" is logical.

**Key Dependencies**:
- `@/context/AuthContext` - User profile with superadmin role
- `@/context/SyncContext` - Offline sync management (pending/failed counts, syncNow)
- `@/hooks/useOfflineStatus` - Online/offline detection
- `@/lib/supabase` - Direct database queries and edge function invocation
- `idb` (IndexedDB) - Client-side storage health checks via `openDB`
- Shadcn UI components (Card, Button, Badge)
- Lucide icons (Database, Activity, AlertCircle, CheckCircle, XCircle, Wifi, WifiOff, Server, HardDrive, RefreshCw, etc.)
- Sonner toast notifications
- Next.js Link for navigation

**Lines of Code**: ~591 lines (comprehensive system dashboard)

## 2. Execution Flow

### Initial Load Sequence
1. Component mounts → Extract `profile`, `isOnline`, sync context (`getPendingCount`, `getFailedCount`, `syncNow`)
2. `useEffect` triggers `checkIndexedDB()` on mount
3. IndexedDB availability test → Set `indexedDBStatus`
4. Render dashboard with:
   - Header with ShieldCheck icon and user name
   - System Health card (4 status items, unknown status initially)
   - Sync Metrics cards (2 cards: pending/failed counts)
   - Quick Actions grid (6 action cards)
   - Action Required banner (conditional, shown when sync issues exist)

### System Health Checks

**Database Connection Test**:
1. Click "Test Connection" → `testDatabaseConnection()`
2. Set `testing=true` → Start timer
3. Query: `.from('shops').select('count').limit(1).single()`
4. Handle PGRST116 error (no rows) as success (connection works)
5. Success: Set `dbStatus='connected'` + Response time toast
6. Error: Set `dbStatus='error'` + Error message toast
7. Update `lastTest` timestamp

**Edge Function Test**:
1. Click "Test Function" → `testEdgeFunction()`
2. Invoke `complete-sale` with test payload: `{ test: true, health_check: true }`
3. Edge function expected to reject test payload (but is reachable)
4. Check error message: `NetworkError` → unreachable (error status)
5. Other errors or success → reachable (healthy status)
6. Response time displayed in toast

**IndexedDB Re-check**:
1. Click "Recheck" → `checkIndexedDB()`
2. Check `'indexedDB' in window` first
3. Open database: `openDB('womaniya-dashboard', 2)`
4. Close database after successful open
5. Success → `indexedDBStatus='healthy'`
6. Error → `indexedDBStatus='error'` (browser incompatibility or private mode)

### Sync Management Flow

**Force Sync**:
1. "Force Sync Now" button in Action Required banner
2. Check online status → Block with toast if offline
3. Set `testing=true` → Call `syncNow()` from SyncContext
4. Success: Toast "Sync completed"
5. Error: Toast "Sync failed"

**View Sync Issues**:
- Click "View Issues" button or "Sync Issues" quick action card
- Navigate to `/superadmin/sync-issues`
- Badge shows failed count if > 0

### Backup Operations

**Export Database**:
1. Click "Export Database" card → `handleExportDatabase()`
2. Set `exporting=true` (shows loading spinner on icon)
3. Sequential data fetches (not parallel) for shop:
   - Shop details (single record)
   - Inventory items (all for shop)
   - QR codes (all for shop)
   - Sales records (all for shop)
   - Profiles (all for shop)
4. Note: stock_lots export commented out (may not exist)
5. Compile into JSON structure with metadata:
   - `exported_at`: ISO timestamp
   - `shop_id`: Current shop
   - `version`: "1.0"
6. Create Blob with pretty-printed JSON (`null, 2`)
7. Download file: `womaniya-backup-{shopName}-{date}.json`
8. Success toast + Set `exporting=false`

**Import Database** (Placeholder):
1. Click "Import Database" card (disabled, shows "Coming Soon")
2. Creates file input for `.json` files
3. Parse JSON → Basic validation (checks `shop_id` and `version`)
4. Shows info toast: "Database import feature will be implemented..."
5. TODO comments outline restore logic needed:
   - Backup current data
   - Clear existing data (optional)
   - Insert imported data
   - Handle ID conflicts
   - Verify integrity

## 3. Business Rules & Assumptions

### Critical Business Logic

**Superadmin Role Access**:
- Page accessible to users with superadmin role
- No explicit role check in component (assumes route protection via layout)
- Displays user's full name in header: "Superadmin • {full_name}"

**Health Check Strategy**:
| Component | Test Method | Success Criteria |
|-----------|-------------|------------------|
| Database | Query shops table | Any response (even PGRST116) |
| Edge Function | Invoke with test payload | Not NetworkError |
| IndexedDB | Open database | Successfully opens |
| Internet | navigator.onLine event | `isOnline === true` |

**Sync Queue Management**:
- Pending syncs: Sales waiting to upload (stored in IndexedDB)
- Failed syncs: Sales that attempted upload and errored
- Force sync: Retries all pending immediately via `syncNow()`
- View metrics: Links to `/superadmin/sync-issues` when count > 0

**Backup Data Scope**:
- Shop-specific export (filtered by `profile.shop_id`)
- Tables included: shops (single), inventory_items, qr_codes, sales, profiles
- **Excluded**: stock_lots (commented out, table may not exist)
- Metadata: `exported_at`, `shop_id`, `version: "1.0"`

**Export File Naming**:
- Pattern: `womaniya-backup-{shop_name}-{YYYY-MM-DD}.json`
- Uses shop name directly (may contain spaces, not sanitized)
- Date from ISO string `.split('T')[0]`

**Quick Actions Grid**:
| Action | Status | Functionality |
|--------|--------|---------------|
| Sync Issues | Active | Links to /superadmin/sync-issues |
| Export Database | Active | Downloads JSON backup |
| Import Database | Disabled | Shows "Coming Soon" |
| Admin Dashboard | Active | Links to /admin |
| System Logs | Disabled | Coming Soon |
| Advanced Tools | Disabled | Coming Soon |

### Implicit Assumptions

1. **Single Shop Context**: Export always for current user's shop (no multi-shop admin)
2. **Superadmin = Technical User**: Comfortable with JSON files, manual database operations
3. **Edge Function Behavior**: Health check relies on error type (NetworkError vs other)
4. **IndexedDB Required**: App assumes browser supports IndexedDB (no fallback)
5. **Online Detection Reliable**: Uses `useOfflineStatus` hook (navigator.onLine based)
6. **No Incremental Backup**: Full export every time (no delta/diff backups)
7. **Sequential Exports**: Data fetched one table at a time (not parallel)

### Edge Cases Not Handled

- **Large Database Export**: 100k+ records may crash browser (no pagination or streaming)
- **Export Failure Recovery**: Partial export lost if error mid-fetch (no transactions)
- **Import Validation**: Basic structure check only (`shop_id` and `version` existence)
- **ID Conflicts on Import**: No strategy for duplicate IDs or foreign key resolution
- **Schema Version Mismatch**: "1.0" version tag not validated during import
- **File Name Special Characters**: Shop name with `/\:*?"<>|` creates invalid filenames

## 4. Risks & Edge Cases

### High Priority Risks

**Large Export Memory Issues**:
- **Risk**: Exporting 50k+ sales, 100k+ QR codes loads entire dataset into memory
- **Impact**: Browser tab crashes, export fails silently
- **Current Mitigation**: None (no limit or warning)
- **Recommended Fix**: 
  - Warn before exporting >10k records
  - Stream export in chunks using async iteration
  - Add progress indicator

**Import Not Implemented**:
- **Risk**: "Import Database" button clickable but does nothing
- **Impact**: User expectation mismatch, confusion
- **Current State**: Disabled flag set, but shows "Coming Soon"
- **Recommended Fix**: Either hide button or implement with conflict resolution

**No Backup Validation**:
- **Risk**: Corrupt export files undetectable until import attempt
- **Impact**: Data loss if backup relied upon for recovery
- **Recommended Fix**: Add checksum/hash to export, validate on import

**Edge Function Test Unreliable**:
- **Risk**: Health check assumes error means reachable (flawed logic)
- **Impact**: False positive if function crashes vs network error
- **Current Logic**: Any response (even error) = healthy, NetworkError = unhealthy
- **Recommended Fix**: Add explicit health check endpoint to edge function

### Medium Priority Risks

**Sync Context Dependency**:
- **Risk**: Page relies on SyncContext always being available
- **Impact**: Crashes if context provider missing
- **Recommended Fix**: Add null checks or default values

**No Export Progress Indicator**:
- **Risk**: Large exports appear frozen (no feedback)
- **Impact**: User thinks app crashed, closes tab mid-export
- **Recommended Fix**: Show progress bar with table-by-table updates

**IndexedDB Check Timing**:
- **Risk**: Checks on mount only, doesn't detect mid-session failures
- **Impact**: Status becomes stale
- **Recommended Fix**: Periodic recheck or event-based updates

**File Name Sanitization**:
- **Risk**: Shop name "My Shop / Store" creates invalid filename
- **Impact**: Download fails or saves with escaped name
- **Recommended Fix**: Sanitize shop name (replace `/\:*?"<>|` with `-`)

### Low Priority Edge Cases

| Edge Case | Description | Impact |
|-----------|-------------|--------|
| Last Test Timestamp | Not persisted, lost on refresh | Shows "Last tested HH:MM:SS" during session only |
| Response Time Display | Shows milliseconds, no baseline | User can't judge if 500ms is good/bad |
| Multiple Exports | No deduplication | User can download same backup repeatedly |
| Stale Health Status | Manual refresh required | No auto-refresh interval |
| Staff Access | No UI blocking | Assumes route protection (correct) |
| Testing State | Single `testing` boolean | All buttons disabled during any test |

## 6. Refactor Signals

### Immediate Refactoring Needs (High Priority)

**Add Export Size Warning**:
- **Current**: No warning before large exports
- **Proposed**: Check total record count, warn if >10k records
- **Implementation**:
  ```typescript
  const totalRecords = await Promise.all([
    supabase.from('inventory_items').select('*', { count: 'exact', head: true }).eq('shop_id', shop_id),
    supabase.from('qr_codes').select('*', { count: 'exact', head: true }).eq('shop_id', shop_id),
    supabase.from('sales').select('*', { count: 'exact', head: true }).eq('shop_id', shop_id),
  ]);
  const total = totalRecords.reduce((sum, r) => sum + (r.count || 0), 0);
  
  if (total > 10000) {
    const confirmed = confirm(`Large export detected (${total} records). This may take several minutes. Continue?`);
    if (!confirmed) return;
  }
  ```

**Parallelize Export Queries**:
- **Current**: Sequential data fetches (one table at a time)
- **Proposed**: Use `Promise.all()` for parallel fetching:
  ```typescript
  const [shopResult, inventoryResult, qrResult, salesResult, profilesResult] = await Promise.all([
    supabase.from('shops').select('*').eq('id', shop_id).single(),
    supabase.from('inventory_items').select('*').eq('shop_id', shop_id),
    supabase.from('qr_codes').select('*').eq('shop_id', shop_id),
    supabase.from('sales').select('*').eq('shop_id', shop_id),
    supabase.from('profiles').select('*').eq('shop_id', shop_id),
  ]);
  ```
- **Benefits**: Faster exports (parallel queries), single error handling block

**Sanitize Export Filename**:
- **Current**: Shop name used directly (may have special chars)
- **Proposed**: Sanitize function:
  ```typescript
  const sanitize = (name: string) => name.replace(/[\/\\:*?"<>|]/g, '-').trim();
  a.download = `womaniya-backup-${sanitize(shop.shop_name)}-${date}.json`;
  ```

**Hide Disabled Quick Actions or Show Progress**:
- **Current**: 3 disabled cards with "Coming Soon" visible
- **Options**:
  1. Hide disabled cards until implemented

  3. Add `isFeatureEnabled` checks
