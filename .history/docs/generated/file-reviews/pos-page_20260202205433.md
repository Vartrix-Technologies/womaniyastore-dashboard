# File Review: pos/page.tsx

## 1. File Responsibility

**Primary Purpose**: Point of Sale (POS) interface for scanning/searching products, building cart, applying discounts, and completing sales transactions.

**Single Responsibility Assessment**: Excellent - Pure presentation layer managing cart state and coordinating child components. All business logic delegated to specialized components (ScanQRButton, ProductSearchDialog, CheckoutDialog).

**Key Dependencies**:
- `@/components/pos/*` - Modular POS components (ScanQRButton, CartList, CartSummary, CheckoutDialog, ProductSearchDialog)
- `@/types/pos.types` - `CartItem` type definitions
- Shadcn UI components (Card, Button, Input)
- Sonner toast notifications
- Lucide icons (QrCode, Trash2, Search, ShoppingBag, Tag)

**Lines of Code**: ~233 lines (lean, well-organized)

## 2. Execution Flow

### Initial State
1. Component mounts with empty cart: `cart: []`, `couponCode: ''`
2. UI renders with two action buttons: Search Products and Scan QR
3. Cart shows empty state with QR icon and prompt

### Product Addition Flows

**QR Scanning Flow**:
1. User clicks "Scan QR" → `ScanQRButton` component handles device camera/scanner
2. QR code scanned → `handleQRScanned(item)` callback triggered
3. Duplicate check: If QR code exists in cart → Error toast, early return
4. Add to cart: `setCart([...cart, item])`
5. Success toast: "Added {category} to cart"

**Search & Add Flow**:
1. User clicks "Search Products" → `setSearchOpen(true)` opens dialog
2. `ProductSearchDialog` displays inventory with filters
3. User selects item → `handleAddFromSearch(item)` callback
4. Duplicate check (same as QR flow)
5. Add to cart without toast (dialog handles feedback)

### Cart Management Flows

**Price Adjustment**:
- User edits price in `CartList` → `handleUpdatePrice(qrCode, newPrice)`
- Updates specific item's `finalPrice` field using map

**Discount Reason**:
- User enters discount reason → `handleUpdateDiscountReason(qrCode, reason)`
- Updates item's `discountReason` field

**Item Removal**:
- User clicks delete button → `handleRemoveItem(qrCode)`
- Filters out item by QR code → Info toast

**Clear Cart**:
- User clicks "Clear Cart" → Browser confirm dialog
- Confirmation → Reset cart and coupon → Info toast

### Coupon Flow
1. User enters coupon code → Auto-converts to uppercase
2. Click "Apply" → `handleApplyCoupon()`
3. Validation: Empty check → Error toast
4. **Placeholder**: Actual validation not implemented → Info toast

**Product Search Dialog Integration**:
- Passes `existingQrCodes` prop (from `cart.map((item) => item.qrCode)`)
- ProductSearchDialog filters out already-added items from selection
- Prevents adding items with sold status (handled internally)

### Checkout Flow
1. User clicks "Complete Sale" (disabled if cart empty)
2. Opens `CheckoutDialog` with cart items and coupon code
3. Dialog handles payment, customer info, bill generation
4. On success: `handleCheckoutComplete()` → Clear cart and coupon → Close dialog

## 3. Business Rules & Assumptions

### Critical Business Logic

**Duplicate Prevention**:
- **Rule**: Same QR code cannot be added twice to cart
- **Reason**: Each physical item has unique QR code (prevents double-charging)
- **Implementation**: Check `cart.some((i) => i.qrCode === item.qrCode)`
- **User Feedback**: Error toast on duplicate attempt

**Price Modification**:
- Staff can override default selling price per item
- No validation on new price (can be zero, negative, or higher than original)
- Discount reason field optional but recommended for audit trail

**Coupon System**:
- Uppercase normalization for consistency
- Not yet implemented (placeholder function)
- Assumed to apply cart-wide discount, not per-item

**Cart State Management**:
- Cart lives in component state (not persisted to storage)
- Browser refresh clears cart (no recovery)
- Cart shared across Search and Scan methods

**Empty Cart Prevention**:
- "Complete Sale" button disabled when `cart.length === 0`
- No maximum cart size limit enforced

### Implicit Assumptions

1. **QR Code Uniqueness**: Each QR code represents one physical item (1:1 mapping)
2. **Item Availability**: Items returned by Search/Scan are available for sale (ProductSearchDialog filters sold items)
3. **No Quantity Field**: Cart doesn't support quantities >1 per item (each item unique via QR)
4. **Single Session**: Cart not persisted across page reloads
5. **Staff Trust**: No validation on price changes (assumes authorized staff only)
6. **Coupon Application**: Coupon applies to entire cart, not specific items (based on CheckoutDialog integration)

### Edge Cases Not Handled

- **Price Validation**: Can set negative or zero prices (no min/max constraints)
- **Cart Recovery**: No auto-save or "Retrieve Last Cart" functionality  
- **Network Loss During Checkout**: Handled by CheckoutDialog component (not visible here)
- **Concurrent Sales**: No cart locking mechanism (each staff has own browser session)
- **Maximum Cart Size**: No limit (could theoretically add thousands of items)

## 4. Risks & Edge Cases

### High Priority Risks

**Duplicate Prevention Already in Search**:
- ProductSearchDialog receives `existingQrCodes` prop
- Already disables "Add to Cart" for items in cart
- Double protection: client-side check in both components

**Cart State Loss on Refresh**:
- **Risk**: Browser refresh or accidental navigation loses entire cart
- **Impact**: Staff must re-scan all items (poor UX, time waste)
- **Recommended Fix**: Persist cart to localStorage with auto-restore on mount
- **Implementation**: 
  ```typescript
  useEffect(() => {
    const saved = localStorage.getItem('pos-cart');
    if (saved) setCart(JSON.parse(saved));
  }, []);
  
  useEffect(() => {
    if (cart.length > 0) {
      localStorage.setItem('pos-cart', JSON.stringify(cart));
    }
  }, [cart]);
  ```

**No Price Change Audit Trail**:
- **Risk**: Staff can change prices without tracking who/why
- **Impact**: Loss prevention issues, no accountability for discounts
- **Current State**: Discount reason field exists but optional
- **Recommended Fix**: Make discount reason required when price reduced >10%

**Browser Confirm Dialog (Non-Modern UX)**:
- **Risk**: `confirm()` blocks UI, looks outdated on tablets
- **Impact**: Poor user experience on touch devices
- **Recommended Fix**: Replace with custom ConfirmDialog component (like in qr-codes page)

### Medium Priority Risks

**Coupon Validation Placeholder**:
- **Risk**: "Apply" button functional but does nothing
- **Impact**: User confusion, expectation mismatch
- **Current State**: Shows "coming soon" toast
- **Recommended Fix**: Either implement validation or hide button until ready

**No Cart Limits**:
- **Risk**: Could theoretically add 10k+ items to cart
- **Impact**: Performance degradation, UI unusable
- **Likelihood**: Low (unrealistic scenario)
- **Recommended Fix**: Add soft limit (e.g., 100 items) with warning

**Component State Management**:
- **Risk**: Parent component manages complex cart state (price updates, removals)
- **Impact**: Component grows as features added
- **Recommended Fix**: Consider useReducer for cart actions or extract to custom hook

### Low Priority Edge Cases

**Uppercase Coupon Normalization**: Assumes all coupons uppercase (may break case-sensitive codes)
**Empty Cart Clear**: Clicking "Clear Cart" with 0 items does nothing (early return, correct behavior)
**Item Category Display**: Toast shows category, but CartList may show different info
**Sticky Summary Card**: Uses `lg:sticky lg:top-20` but may clip on short screens

## 6. Refactor Signals

### Immediate Refactoring Needs (High Priority)

**Replace Browser Confirm with Custom Dialog**:
- **Current**: `confirm('Are you sure...')` blocks UI
- **Proposed**: Use `ConfirmDialog` component (already exists in codebase)
- **Example**:
  ```typescript
  const [confirmOpen, setConfirmOpen] = useState(false);
  
  <ConfirmDialog
    open={confirmOpen}
    onOpenChange={setConfirmOpen}
    onConfirm={() => { setCart([]); setCouponCode(''); }}
    title="Clear Cart"
    description="Are you sure you want to remove all items?"
  />
  ```
- **Benefits**: Consistent UX, better mobile experience

**Add Cart Persistence**:
- **Current**: Cart lost on refresh
- **Proposed**: localStorage with auto-restore
- **Critical for**: Tablet POS where accidental closes common
- **Implementation**: ~10 lines with useEffect hooks

**Extract Custom Hook: `useCart`**:
- **Current**: Cart management logic in component (100+ lines)
- **Proposed**:
  ```typescript
  const {
    cart,
    addItem,
    removeItem,
    updatePrice,
    updateDiscountReason,
    clearCart,
  } = useCart();
  ```
- **Benefits**: Testable logic, reusable for multi-POS setups, cleaner component

### Medium Priority Refactoring

**Implement Coupon Validation**:
- **Current**: Placeholder function
- **Proposed**: API call to validate coupon code
- **Alternative**: Hide coupon section until implemented

**Add Price Change Validation**:
- **Current**: No constraints on new price
- **Proposed**: Warn if price <50% of original or <0
- **Example**:
  ```typescript
  if (newPrice < item.originalPrice * 0.5) {
    // Show warning dialog: "Large discount requires manager approval"
  }
  ```

**Cart State with useReducer**:
- **Current**: Multiple setState calls for cart operations
- **Proposed**: useReducer with typed actions (ADD_ITEM, REMOVE_ITEM, UPDATE_PRICE, etc.)
- **Benefits**: Better TypeScript support, centralized state logic

**Empty State Enhancement**:
- **Current**: Generic "Scan or search" message
- **Proposed**: Contextual help based on time of day, last action, etc.

### Low Priority Refactoring

**Memoize Existing QR Codes**:
- `existingQrCodes={cart.map((item) => item.qrCode)}` recalculates on every render
- Use `useMemo` to prevent unnecessary ProductSearchDialog re-renders

**Extract Coupon Section**:
- Lines 189-206 (coupon input) → `<CouponInput value={couponCode} onChange={setCouponCode} onApply={handleApplyCoupon} />`

**Add Loading States**:
- Show loading indicator during QR scan, search, checkout

**Accessibility Improvements**:
- Add ARIA labels to action buttons
- Keyboard shortcuts (e.g., Ctrl+Enter for checkout, Esc to clear cart)

- Well-structured component with clear responsibilities
- Good use of modular child components
- Type-safe with TypeScript

**Primary Concerns**:
