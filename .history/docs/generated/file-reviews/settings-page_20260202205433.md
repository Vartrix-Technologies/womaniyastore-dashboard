# File Review: settings/page.tsx

## 1. File Responsibility

**Primary Purpose**: Comprehensive settings management interface for shop configuration, product categories, sizes, expense categories, and tax rates across tabbed sections.

**Single Responsibility Assessment**: Moderate - handles multiple CRUD operations for different entity types. Could benefit from extracting tab sections into separate components, but grouping under "settings" is logical.

**Key Dependencies**:
- `@/lib/supabase` - Direct database queries for all CRUD operations
- `@/context/AuthContext` - Shop ID and role authorization
- `@/types` - Type definitions for Shop, Category, Size
- Shadcn UI components (Tabs, Dialog, Input, Label, Button, Card)
- Sonner toast notifications
- Lucide icons (Settings, Store, Receipt, Tags, Ruler, Plus, Edit, Trash2, ArrowLeft)
- Next.js router for navigation

**Lines of Code**: ~887 lines (large component with 5 tabs and 3 dialogs)

## 2. Execution Flow

### Initial Load Sequence
1. Component mounts → Extract `profile.shop_id` and `profile.role` from auth context
2. `useEffect` triggers `loadData()` when `profile.shop_id` available
3. Sequential data fetches (not parallel despite no dependencies):
   - **Shop**: `.single()` query for shop details → Populate `shopForm` state
   - **Categories**: `.order('name')` for product categories
   - **Sizes**: `.order('sort_order')` for size templates
   - **Expense Categories**: `.order('name')` for financial tracking
4. UI renders with tabs (different tabs for admin vs staff)
5. Loading state shows full skeleton during fetch

### Tab Navigation Flow
- Default tab: "shop" (Shop Details)
- Tabs available (for admin/owner): Shop Details, Tax Settings, Categories, Sizes, Expense Categories
- **Staff Role**: Only sees placeholder message ("Staff settings coming soon")
- **Admin/Owner**: All 5 tabs accessible
- Tab state managed by Tabs component (not persisted on refresh)

### Shop Settings Update Flow
1. User edits fields in Shop Details or Tax Settings tabs
2. Form state updates via `setShopForm({ ...shopForm, field: value })`
3. Click "Save Changes" → `handleSaveShop()`
4. `.update()` query on shops table by `profile.shop_id`
5. Success: Toast notification + Reload data to sync state
6. Error: Toast with error message

### Category Management Flow (Product, Expense, Size similar)

**Add Flow**:
1. Click "Add" button → `handleAddCategory()`
2. Reset form → `setEditingCategory(null)` → `setCategoryDialog(true)`
3. User fills form → Click "Add" → `handleSaveCategory()`
4. `.insert()` with `shop_id` → Success toast → Close dialog → Reload data

**Edit Flow**:
1. Click edit icon → `handleEditCategory(category)`
2. Populate form with existing data → `setEditingCategory(category)`
3. Open dialog → User modifies → Click "Update" → `handleSaveCategory()`
4. `.update()` query by category ID → Reload data

**Delete Flow**:
1. Click delete icon → Browser confirm dialog (`confirm()`)
2. Confirmation → `handleDeleteCategory(id)`
3. **Expense Category Special Case**: Check if used in `financial_transactions`
4. If not used: `.delete()` → Success toast → Reload data
5. If used: Error toast "Cannot delete category with existing expenses"

### Expense Category Safe Delete
- Checks `financial_transactions` for references before deletion
- Uses `{ count: 'exact', head: true }` for efficient count (no data fetch)
- Product categories and sizes do NOT have this protection

## 3. Business Rules & Assumptions

### Critical Business Logic

**Shop Settings**:
- **Shop Name**: Required field (marked with *)
- **Bill Prefix**: Used for invoice numbering (e.g., "WMY-20241222143022")
- **Tax Rate**: Global shop tax percentage (0-100, applies to all future sales)
- **Address/Phone**: Optional fields (nullable in database)

**Category Hierarchy**:
- **Product Categories**: For inventory items (e.g., "Sarees", "Suits", "Kurtis")
- **Expense Categories**: For financial tracking (e.g., "Rent", "Utilities", "Salaries")
- **Sizes**: Predefined size templates with sort order (e.g., "S", "M", "L", "XL")

**Sort Order Logic (Sizes)**:
- New sizes default to `sizes.length` (append to end)
- Manual sort order allows custom arrangement
- UI displays in ascending sort order
- No drag-and-drop (manual number editing only)

**Role-Based Access**:
- **Staff**: Completely blocked from settings (placeholder message only)
- **Admin/Owner**: Full access to all tabs
- No granular permissions (all-or-nothing for non-staff)

**Deletion Constraints**:
| Entity | Orphan Check | Reason |
|--------|--------------|--------|
| Expense Categories | ✅ Yes | Checks `financial_transactions.category_id` |
| Product Categories | ❌ No | May orphan inventory items |
| Sizes | ❌ No | May orphan inventory items with size references |

### Implicit Assumptions

1. **Single Shop Context**: User always operates within their `shop_id` (multi-tenancy enforced by RLS)
2. **Immediate Sync**: All changes immediately reflect across app (no caching)
3. **No Undo**: Deletions permanent (no soft delete or recovery)
4. **Unique Names**: No uniqueness validation (can create duplicate category names)
5. **Tax Rate Format**: Stored as decimal (e.g., 18 for 18%), not fraction
6. **Sort Order Conflicts**: Multiple sizes can have same sort order (display order undefined)

### Edge Cases Not Handled

- **Orphaned References**: Deleting categories/sizes with existing inventory items
- **Concurrent Edits**: Two admins editing same category simultaneously
- **Invalid Tax Rates**: Can enter negative or >100% tax rates (HTML min/max helps but not enforced)
- **Empty Names**: Validation requires `.trim()` check, but can still submit whitespace
- **Bill Prefix Collisions**: Changing prefix doesn't update existing bill numbers

## 4. Risks & Edge Cases

### High Priority Risks

**No Orphan Prevention for Categories/Sizes**:
- **Risk**: Deleting category with 1000 inventory items → Data integrity issue
- **Impact**: Inventory items show "No category", reports broken, data cleanup required
- **Current State**: Only expense categories check for usage
- **Recommended Fix**: Add reference checks before deletion:
  ```typescript
  const { count } = await supabase
    .from('lots')
    .select('*', { count: 'exact', head: true })
    .eq('category_id', categoryId);
  
  if (count > 0) {
    toast.error(`Cannot delete category with ${count} items. Please reassign first.`);
    return;
  }
  ```

**Browser Confirm Dialog (Poor UX)**:
- **Risk**: Three separate `confirm()` calls blocking UI
- **Impact**: Looks unprofessional, poor touch device experience, inconsistent with rest of app
- **Lines**: Category delete, Size delete, Expense category delete
- **Recommended Fix**: Replace with ConfirmDialog component (used in other pages like QR codes)

**No Input Validation**:
- **Risk**: Can save empty category names, extreme tax rates, invalid data
- **Impact**: Data corruption, calculation errors, UI display issues
- **Examples**:
  - Tax rate 150% → Incorrect sale amounts
  - Empty category name → Invisible in dropdowns
  - Bill prefix with special characters → Potential display issues
- **Current State**: Only expense category does `.trim()` check, others don't
- **Recommended Fix**: Add validation before save operations

**Tax Rate Change Impact**:
- **Risk**: Changing tax rate doesn't update pending sales or historical data
- **Impact**: Inconsistent financial records, audit issues
- **Recommended Fix**: Warn users: "Tax rate change only applies to future sales"

### Medium Priority Risks

**Sort Order Management**:
- **Risk**: No UI to reorder sizes after creation (only edit individually)
- **Impact**: Tedious to maintain logical size order (S, M, L, XL)
- **Recommended Fix**: Add drag-and-drop reordering or bulk sort order editor

**No Name Uniqueness Validation**:
- **Risk**: Can create 5 categories all named "Other"
- **Impact**: Confusing dropdowns, reporting issues
- **Recommended Fix**: Check for duplicates before insert/update

**Sequential Data Loading**:
- **Risk**: 4 sequential queries on page load (shop, categories, sizes, expense_categories)
- **Impact**: Slower load time (sum of all queries, not parallel)
- **Recommended Fix**: Use `Promise.all()` for parallel fetching or single RPC function

**Form State Out of Sync**:
- **Risk**: Editing in one tab, switching tabs without saving → Changes lost
- **Impact**: User confusion, data loss
- **Current State**: No dirty state tracking or warning
- **Recommended Fix**: Add "Unsaved changes" warning or auto-save

### Low Priority Edge Cases

| Edge Case | Description | Impact |
|-----------|-------------|--------|
| Staff Tab | Shows "Coming soon" placeholder | Takes tab space, better to hide entirely |
| Description Field | Product categories have description, expense don't | Inconsistent schema |
| Dialog Reuse | 3 nearly identical dialogs (Category, Size, Expense) | Code duplication |
| Loading State | Full skeleton even if only one entity loading | Could be more granular |
| Tax Input | Has min/max HTML attributes (0-100) | Client-side only, not enforced |

## 6. Refactor Signals

### Immediate Refactoring Needs (High Priority)

**Add Orphan Checks Before Deletion**:
- **Current**: Only expense categories check usage
- **Proposed**: Add reference checks for categories and sizes:
  ```typescript
  // For categories
  const { count } = await supabase
    .from('lots')
    .select('*', { count: 'exact', head: true })
    .eq('category_id', categoryId);
  
  // For sizes
  const { count } = await supabase
    .from('inventory_items')
    .select('*', { count: 'exact', head: true })
    .eq('size_id', sizeId);
  ```
- **Critical for**: Data integrity, preventing broken reports

**Replace Browser Confirms**:
- **Current**: 3 instances of `confirm('Are you sure...')`
- **Proposed**: Use ConfirmDialog component (consistent with QR codes page)
- **Lines**: ~211, ~275, ~337

**Parallelize Data Loading**:
- **Current**: 4 sequential await calls
- **Proposed**: Use `Promise.all()`:
  ```typescript
  const [shopResult, categoriesResult, sizesResult, expenseCatsResult] = await Promise.all([
    supabase.from('shops').select('*').eq('id', shopId).single(),
    supabase.from('categories').select('*').eq('shop_id', shopId).order('name'),
    supabase.from('sizes').select('*').eq('shop_id', shopId).order('sort_order'),
    supabase.from('expense_categories').select('*').eq('shop_id', shopId).order('name'),
  ]);
  ```
- **Benefits**: Load time = slowest query, not sum of all

**Add Input Validation**:
- **Current**: Minimal validation (only `.trim()` on some fields)
- **Proposed**: Validate before save:
  - Tax rate: 0-100 range, number type
  - Category/size names: Non-empty after trim, max length (e.g., 50 chars)
  - Bill prefix: Alphanumeric only, max 10 chars
  - Shop name: Required, non-empty

### Medium Priority Refactoring

**Extract Tab Sections into Components**:
- **Current**: 887 lines, all tabs in one file
- **Proposed**:
  ```
  <ShopSettingsTab shop={shop} onSave={handleSaveShop} />
  <TaxSettingsTab taxRate={shopForm.tax_rate} onSave={handleSaveShop} />
  <CategoriesTab categories={categories} onAdd={...} onEdit={...} onDelete={...} />
  <SizesTab sizes={sizes} ... />
  <ExpenseCategoriesTab expenseCategories={expenseCategories} ... />
  ```
- **Benefits**: Testable, maintainable, ~150-200 lines per component

**Consolidate CRUD Dialogs**:
- **Current**: CategoryDialog, SizeDialog, ExpenseCategoryDialog nearly identical
- **Proposed**: Generic `<EntityDialog>` component with dynamic fields:
  ```typescript
  <EntityDialog
    title={editingEntity ? 'Edit Category' : 'Add Category'}
    fields={[
      { name: 'name', label: 'Name', required: true },
      { name: 'description', label: 'Description', required: false },
    ]}
    onSave={handleSave}
  />
  ```
- **Benefits**: DRY principle, consistent behavior

**Add Unsaved Changes Warning**:
- **Current**: Tab switch loses unsaved edits silently
- **Proposed**: Track dirty state, show confirmation before tab switch
- **Implementation**: Compare current form state with last saved state

**Extract Custom Hook: `useSettings`**:
- **Current**: State management scattered across component
- **Proposed**:
  ```typescript
  const {
    shop, categories, sizes, expenseCategories,
    loading, error,
    saveShop, addCategory, editCategory, deleteCategory,
    addSize, editSize, deleteSize,
    addExpenseCategory, editExpenseCategory, deleteExpenseCategory,
  } = useSettings(profile.shop_id);
  ```

### Low Priority Refactoring

**Add Drag-and-Drop Size Reordering**:
- **Current**: Manual sort_order number editing

- **Benefits**: Better UX for managing size order

**Memoize Table Rows**:
