## 1. File Responsibility

### Primary Responsibility
Admin interface for viewing, creating, editing, and deleting staff attendance records with calendar and tabular views.

### Role in the System
- Displays attendance logs with filtering, sorting, and pagination
- Provides calendar view per staff member
- Supports manual attendance entry and corrections
- Exports attendance data to CSV

### What This File Intentionally Does NOT Do
- **Clock in/out actions**: Uses separate dialogs for CRUD operations
- **Payroll calculation**: Only tracks hours, no salary computation
- **Owner/Superadmin tracking**: Excludes these roles from attendance system
- **Real-time updates**: Manual refresh required

## 2. Execution Flow

### `AdminAttendancePage` Component

**Trigger:** Route navigation to `/admin/attendance`

**Input Expectations:**
- User must be authenticated admin/owner with valid `profile.shop_id`

**Internal Steps:**
1. Initialize date range (last 7 days by default)
2. On mount/filter change, fetch staff and attendance logs
3. Apply client-side search and sorting
4. Paginate results for display

**Side Effects:**
- **DB Read**: `profiles` and `attendance_logs` tables
- **State**: Multiple filter/sort/pagination states

**Output/UI:**
- Two tabs: Calendar view and Logs table
- Filter controls (date range, staff, status, search)
- Sortable table with edit/delete actions
- Pagination controls

### `loadData()`

**Trigger:** `useEffect` on `profile.shop_id`, `dateRange`, `filterStaffId`, `filterStatus` changes

**Steps:**
1. Fetch staff excluding owner/superadmin roles
2. Build attendance query with date range and filters
3. Apply server-side filters (staff, status types)
4. Client-side filter to remove any owner/superadmin logs that slipped through
5. Set default staff for calendar view

**Key Queries:**
```
profiles: shop_id = X, role NOT IN (owner, superadmin)
attendance_logs: shop_id = X, date range, deleted_at IS NULL
```

**Status Filters Applied Server-Side:**
| Filter | Query Condition |
|--------|-----------------|
| `in-progress` | `clock_out IS NULL` |
| `completed` | `clock_out IS NOT NULL` |
| `manual` | `is_manual_entry = true` |
| `edited` | `edited_at IS NOT NULL` |

### `calculateHours(clockIn, clockOut, breakMinutes)`

**Trigger:** Called for each log row display and export

**Steps:**
1. Parse start/end timestamps (end defaults to now if null)
2. Calculate total minutes difference
3. Subtract break minutes
4. Return hours as string (1 decimal)

**Key Behavior:** Returns live hours for in-progress shifts

### `toggleSort(column)`

**Trigger:** Click on sortable table header

**Steps:**
1. If same column, toggle asc/desc
2. If different column, set new column with desc default
3. Reset to page 1

**Sortable Columns:** date, staff (name), hours

### Client-Side Processing Pipeline

```
logs (raw) → filteredLogs (search) → sortedLogs (sort) → paginatedLogs (slice)
```

## 3. Business Rules & Assumptions

### Explicit Business Rules

| Rule | Implementation |
|------|----------------|
| Owner/Superadmin excluded from attendance | Query filter + client-side filter |
| Deleted records hidden | `deleted_at IS NULL` filter |
| Default date range is last 7 days | State initialization |
| In-progress shows live hours | calculateHours uses `new Date()` as end |
| Records can be manually created | Admin create dialog |
| Records are soft-deleted | deleted_at timestamp, not hard delete |

### Implicit Assumptions
- Admin/owner has permission to view/edit all shop attendance
- Attendance records have staff_id linking to profiles
- Break time is tracked in minutes
- Clock times are stored as ISO timestamps

### Invariants
- Attendance logs are shop-scoped
- Staff selector in calendar always has valid staff_id if staff exist
- edited_by tracks who made modifications

## 4. Risks & Edge Cases

### High Priority

| Risk | Impact | Mitigation |
|------|--------|------------|
| Timezone issues | Wrong date filtering | Uses ISO string dates, but display depends on client TZ |
| Large date ranges | Performance/memory | No server-side pagination, all logs loaded |

### Medium Priority

| Risk | Impact | Mitigation |
|------|--------|------------|
| Clock-out in future | Negative hours | calculateHours uses Math.max(0, ...) |
| Missing staff profile | Broken display | Join returns null, shown as undefined |
| Concurrent edits | Data conflicts | No optimistic locking |

### Low Priority

| Risk | Impact | Mitigation |
|------|--------|------------|
| Empty staff list | No calendar | Shows "No staff members found" message |
| Very long shifts | Unlikely hours | No validation on maximum hours |
| Search case sensitivity | Missed results | toLowerCase() applied |

## 6. Refactor Signals

### Structural Issues
1. **Large component**: 607 lines with multiple responsibilities. Consider extracting:
   - Filter/search logic to custom hook
   - Table component to separate file
   - Pagination component to shared
2. **Duplicate filter logic**: Checklists filter applied twice (for display and empty state check)
3. **No loading state for dialogs**: Edit/delete operations don't show inline loading

### Scalability Concerns
1. **Client-side sorting/pagination**: All data loaded upfront. For large datasets:
   - Move sorting to server (ORDER BY)
   - Implement cursor-based pagination
2. **No caching**: Data re-fetched on every filter change. Consider SWR/React Query.
3. **Date range unbounded**: User could select years of data

### Pattern Misalignments
1. **Mixed concerns**: Page component handles data fetching, state, rendering, calculations
2. **No error boundaries**: Errors in dialogs could crash page
3. **Manual date handling**: Could use date-fns more consistently

### Suggested Improvements (No Code)
- Extract `useAttendanceData` hook for data fetching and filtering
- Add maximum date range limit (e.g., 90 days)
- Server-side pagination for logs > 100
- Add loading indicators on filter changes
- Debounce search input

| **Dual View Modes** | Calendar + table gives flexibility—common in enterprise HR apps (BambooHR, Gusto) |

| **Real-time Hours Calc** | Live calculation for open shifts shows attention to detail |
| **Comprehensive Filtering** | Status + role + date + search covers all use cases |
| **CSV Export** | Practical utility feature for business reporting |

### What Feels Dated or Unpolished ❌

| Issue | Impact | Premium Comparison |
|-------|--------|-------------------|
| **No visual time blocks** | Just numbers, no timeline visualization | Google Calendar shows time blocks visually |
| **Basic table styling** | Plain alternating rows | Notion/Linear use subtle shadows, hover states |
| **No summary dashboard** | Jumps straight to data | Shopify shows summary cards before details |

| **Dialog-heavy workflow** | 3 separate dialogs (create/edit/delete) | Sheet/drawer pattern feels more modern |
