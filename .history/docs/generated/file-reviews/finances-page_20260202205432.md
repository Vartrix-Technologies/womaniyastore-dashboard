## 1. File Responsibility

**Primary Purpose**: Comprehensive financial dashboard with expense management, revenue tracking, category breakdown visualization, vendor profit reporting, and CSV export.

**Role in the System:**  
Financial analytics hub for shop owners. Tracks cash flow, calculates profit margins, shows expense patterns by category, and provides vendor-wise sales analysis.

**What This File Intentionally Does NOT Do:**  
- Does NOT process payments (handled by POS)
- Does NOT manage invoices/receivables
- Does NOT edit past transactions (audit trail)
- Does NOT integrate with accounting software
- Does NOT handle tax calculations/filing

**Key Dependencies:**
- `@/context/AuthContext` - Shop ID authorization
- `@/lib/supabase` - Direct database queries
- `@/hooks` - `useDateFilter`, `useServerPagination`, `useSortableTable`, `useDebouncedSearch`
- `@/components/shared/DateFilterTabs` - Date range selection
- `@/components/shared/StatsCardGrid` - Summary stat cards
- `@/components/shared/SortableHeader` - Sortable table headers
- `sonner` - Toast notifications (used consistently here!)

## 3. Business Rules & Assumptions

**Explicit Rules:**
- Net Profit = Revenue - Expenses
- Profit Margin = (Net Profit / Revenue) × 100
- Inventory Value = Sum of selling prices (not cost!)
- Cash Flow = Net Profit (redundant metric currently)
- Date filter applies to all queries consistently

**Implicit Assumptions:**
- All sales have `total_amount` (no null check)
- Vendor tracking requires `vendor_name` in lots
- Expense categories are shop-specific
- Timezone: Uses client local time

**Known Limitations:**
- Category breakdown based on paginated data only
- "All Time" actually shows 1 year of data
- No expense editing after creation
- No expense deletion

## 4. Risks & Edge Cases

| Risk | Severity | Description |
|------|----------|-------------|
| Inventory value misleading | **Medium** | Uses selling price, not cost - inflates asset value |
| Category breakdown incomplete | **Medium** | Only from current page, not full dataset |
| "All Time" misleading | **Low** | Actually 1 year lookback |
| No expense edit/delete | **Medium** | Mistakes cannot be corrected |
| Vendor report empty | **Low** | Requires vendor_name in lots - may confuse users |

**Edge Cases Handled:**
- ✅ Division guard for profit margin (0% if no revenue)
- ✅ "Unknown Vendor" fallback
- ✅ Empty state with guidance
- ✅ Separate empty states for "no data" vs "no filter results"

**Edge Cases NOT Handled:**
- Future dates allowed for expenses
- Negative amounts allowed (no min constraint)
- Very large numbers - no overflow handling
- Deleted categories show "Uncategorized" only

**Vendor Report Nested Query Performance** (Medium):
- **Risk**: Fetches full sales → sale_items → inventory_items → lots chain
- **Impact**: Slow queries for shops with thousands of sales
- **Current State**: No pagination on vendor report
- **Recommended Fix**: Use server-side aggregation or Supabase RPC function

**Expense Form Validation** (Medium):
- **Risk**: Only checks if fields exist, not if values are valid
- **Impact**: Can submit empty strings, whitespace, or extreme values
- **Current State**: `parseFloat('')` → NaN, database may reject or store 0
- **Recommended Fix**: Add explicit validation (min/max amounts, date range limits)

**Timezone Issues** (Low):
- **Risk**: Date filter uses client-side `new Date()` without timezone normalization
- **Impact**: Off-by-one-day errors for users in different timezones
- **Example**: Shop in India, server in UTC → "Today" filter may include yesterday's sales
- **Recommended Fix**: Use shop's timezone setting or server-side date calculation

### Low Priority Edge Cases

**Category Name Duplicates**: Case-sensitive comparison allows "rent" and "Rent" as separate categories
**Color Cycling**: After 6 categories, colors repeat (may confuse users)
**Empty Expense List**: Good empty state ("No expenses recorded" with prompt)
**Stale Data**: No real-time updates when expenses added in another tab
**Export Memory**: Large exports (10k+ expenses) load into browser memory
