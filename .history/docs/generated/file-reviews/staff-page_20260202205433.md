## 1. File Responsibility

### Primary Responsibility
Staff management interface for viewing, editing, and toggling active status of staff members within the current shop.

### Role in the System
- Displays a filterable, searchable list of staff profiles
- Allows editing staff details (name, phone, role, max discount, active status)
- Does NOT allow creating new users (staff must self-register via login page)
- Provides quick stats cards for filtering by status/role

### What This File Intentionally Does NOT Do
- **User creation**: Cannot create new auth users from client (Supabase limitation)
- **Delete users**: Only deactivates staff, no permanent deletion
- **Cross-shop access**: Only shows staff from current shop
- **Password management**: No password reset/change functionality

### Key Dependencies
| Dependency | Purpose |
|------------|---------|
| `@/context/AuthContext` | Current user profile (shop_id, role) |
| `@/lib/supabase` | Database queries for profiles |
| `next/navigation` | Router for back navigation |
| `sonner` | Toast notifications |
| Shadcn UI | Card, Button, Dialog, Input, Badge, Switch, Select, Tabs |
| Lucide Icons | Users, Plus, Edit, UserX, ArrowLeft, Search |

## 2. Execution Flow

### `StaffPage` Component

**Trigger:** Route navigation to `/admin/staff`

**Input Expectations:**
- User must be authenticated with valid `profile.shop_id`

**Internal Steps:**
1. On mount, check if `profile?.shop_id` exists
2. Fetch all profiles with `role = 'staff'` for current shop
3. Sort by `created_at` descending (newest first)
4. Display in filterable table with stats cards

**Side Effects:**
- **DB Read**: `profiles` table (filtered by shop_id and role)
- **DB Write**: Profile updates (on edit/toggle status)
- **State**: Local filter/search state management

**Output/UI:**
- Stats cards (Total, Active, Admin, Staff counts)
- Search input with name/phone filtering
- Status tabs (All/Active/Inactive)
- Role dropdown filter
- Staff table with edit/deactivate actions

### `loadStaff()`

**Trigger:** `useEffect` on `profile.shop_id` change

**Steps:**
1. Query `profiles` where `shop_id` matches AND `role = 'staff'`
2. Order by `created_at` descending
3. Update local state

**Key Point:** Only fetches `role = 'staff'`, so admins/owners/superadmins are NOT shown in list (but counted in stats via client-side filter).

### `handleEditStaff(member)`

**Trigger:** Edit button click in table row

**Steps:**
1. Populate form with member data
2. Open dialog modal

**Side Effects:** Sets `editingStaff` and `formData` state

### `handleSubmit()`

**Trigger:** Form submit in edit dialog

**Steps:**
1. Validate `full_name` is not empty
2. Update `profiles` table with form data
3. If editing self, reload page to refresh AuthContext
4. Otherwise, show success toast and reload list

**Side Effects:**
- **DB Write**: `profiles` UPDATE
- **Navigation**: Page reload if self-edit

### `handleToggleActive(member)`

**Trigger:** Deactivate/Activate button click

**Steps:**
1. Update `is_active` to opposite value
2. Show success toast
3. Reload staff list

**Side Effects:** DB Write to `profiles.is_active`

## 3. Business Rules & Assumptions

### Explicit Business Rules

| Rule | Implementation |
|------|----------------|
| Staff cannot be created from admin panel | Toast info message directing to login page |
| Max discount is 0-100 percent | Input min/max constraints |
| Inactive staff cannot log in | `is_active` flag checked at login |
| Only staff role shown in table | Query filters `role = 'staff'` |
| Self-edit triggers page reload | To refresh AuthContext with updated profile |

### Implicit Assumptions
- User has `admin`, `owner`, or `superadmin` role to access this page
- `shop_id` is always present for authenticated users
- Staff profiles are soft-deactivated, never deleted
- Phone number format is not validated (placeholder suggests +91 format)

### Invariants
- Staff list only contains profiles from current shop
- Profile `id` is immutable (used as table key)
- Role hierarchy: superadmin > owner > admin > staff

## 4. Risks & Edge Cases

### High Priority

| Risk | Impact | Mitigation |
|------|--------|------------|
| Self-deactivation | User locked out | No check prevents admin from deactivating self |
| Stats count mismatch | Admin count includes owner/superadmin but table doesn't show them | Confusing UX, not data loss |

### Medium Priority

| Risk | Impact | Mitigation |
|------|--------|------------|
| Concurrent edits | Last write wins | No optimistic locking |
| Large staff list | Performance degradation | No pagination, all loaded at once |
| No confirmation on deactivate | Accidental deactivation | Single-click toggle |

### Low Priority

| Risk | Impact | Mitigation |
|------|--------|------------|
| Phone format not validated | Inconsistent data | Only placeholder hint provided |
| Empty search results | User confusion | Conditional message based on filter state |

## 6. Refactor Signals

### Structural Issues
1. **Stats vs Table mismatch**: Stats count admin/owner/superadmin but table doesn't show them. Consider separate queries or clarifying UI labels.
2. **No loading state for actions**: Edit/toggle buttons don't show loading state during async operations.
3. **Form validation minimal**: Only checks `full_name`, no phone format or discount range validation with error messages.

### Scalability Concerns
1. **No pagination**: All staff loaded at once. For shops with many staff (unlikely but possible), add pagination.
2. **Client-side filtering only**: Search/filter happens after full data load. For large datasets, server-side filtering recommended.

### Pattern Misalignments
1. **Could use Server Component**: Initial staff list could be server-fetched, with client components for interactivity.
2. **No React Query/SWR**: Manual loading state management. Consider using data fetching library for caching and refetching.

### Suggested Improvements (No Code)
- Add confirmation dialog for deactivation
- Prevent self-deactivation
- Add loading spinner to action buttons
- Consider virtualized list for performance

## 7. Critic Section: Premium & Modern Assessment

### Critical Gap: No User Creation Flow 🚨

**This is the biggest UX failure on this page.** The "Add Staff" button shows a toast telling users to go elsewhere. This is:
- **Confusing**: Button suggests functionality that doesn't exist
- **Frustrating**: Admin must explain to new staff how to self-register
- **Unprofessional**: Every competitor (Gusto, Deputy, Homebase) lets you invite staff

**What premium apps do:**
```
┌────────────────────────────────────────────────────┐
│ INVITE STAFF                                       │
│ ┌─────────────────────────────────────────────┐   │
│ │ Email: [________________________]           │   │
│ │ Role:  [Staff          ▼]                  │   │
│ │                                              │   │
│ │ They'll receive an invite link to join      │   │
│ └─────────────────────────────────────────────┘   │
│                              [Send Invite]         │
└────────────────────────────────────────────────────┘
```

### What Works Well ✅

| Feature | Why It's Good |
|---------|---------------|
| **Stats Cards as Filters** | Click "Active" to filter—discoverable UX pattern |
| **Debounced Search** | 300ms debounce prevents jank |
| **Role-Based Permissions** | Discount limits per staff is smart business logic |
| **Active/Inactive Toggle** | Soft disable is better than delete |

### What Feels Dated or Unpolished ❌

| Issue | Impact | Premium Comparison |
|-------|--------|-------------------|
| **Broken "Add Staff" flow** | Critical—users expect this to work | Gusto sends email invites |
| **No staff photos/avatars** | Impersonal list | Google Admin shows profile pictures |
| **Single-click deactivate** | Accidental deactivation | Slack requires confirmation |
| **No onboarding checklist** | New staff drop-off | Deputy shows training completion |
| **Plain permission model** | Just "max discount" | Shopify has granular permission checkboxes |
| **No activity log** | Can't see what staff did | Every HR app shows recent activity |

### Missing Premium Features

1. **Email Invite System**
   - Send invite link via email/SMS
   - Track pending invites
   - Resend/revoke invites
   - Magic link authentication

2. **Staff Profiles**
   - Photo upload
   - Emergency contact
   - Employment start date
   - Document uploads (ID, certificates)

3. **Granular Permissions**
   ```
   ┌─────────────────────────────────────────────────┐
   │ PERMISSIONS FOR: Staff Member                  │
   │ ☑ View Inventory    ☐ Edit Inventory           │
   │ ☑ Process Sales     ☐ Give Discounts > 10%     │
   │ ☐ View Reports      ☐ Manage Staff             │
   │ ☑ Clock In/Out      ☑ View Own Attendance      │

   ```

4. **Activity Timeline**
   - "Rahul processed 15 sales today"
   - "Priya clocked in late 3 times this week"
   - "New: Amit joined yesterday"
