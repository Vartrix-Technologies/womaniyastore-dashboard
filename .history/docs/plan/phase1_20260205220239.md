## Critical Gaps (P1 - Must Fix)

### 1. Staff Creation Flow Missing ✅ COMPLETED
- **Issue**: No way to create new staff users
- **Current**: Toast says "register via login page" but no public signup exists
- **Fix Options**:
  - A) Admin invite via Supabase Admin API (recommended) ✅ IMPLEMENTED
  - B) Self-service signup with shop code validation
- **Effort**: 4-6 hours
- **Resolution**: Implemented superadmin-only user creation with Edge Function, mandatory password change on first login, and user deactivation with auth ban.

### 2. Bill Sending Not Functional ✅ COMPLETED
- **Issue**: PDF generation exists, but no actual delivery mechanism
- **Current**: Falls back to `mailto:` (unreliable)
- **Fix Options**:
  - A) WhatsApp share link (simple, mobile-friendly) ✅ IMPLEMENTED
  - B) Email via Edge Function + Resend/SendGrid
- **Effort**: 2-4 hours (WhatsApp) / 6-8 hours (Email)
- **Resolution**: Added WhatsApp share button with formatted bill message. Uses Web Share API on mobile for native sharing, falls back to WhatsApp link on desktop.

### 3. Offline Sync Incomplete ✅ AUDITED & ENHANCED
- **Issue**: IndexedDB operations exist but sync queue not visible
- **Current**: `SyncContext.tsx` has basic structure
- **Audit Needed**: Verify `lib/offline/` completeness
- **Effort**: 4-8 hours (audit + fixes)
- **Audit Findings**: Core infrastructure is solid (IndexedDB, auto-sync, retry logic). Gaps were visibility-focused.
- **Enhancements Made**:
  - Created modular `lib/offline/` with config, inventory-cache, and clean exports
  - Added `OFFLINE_CONFIG` for centralized settings (sync intervals, retry backoff, feature flags)
  - Added `SyncEventBus` for future event-driven extensions
  - Created `useSyncStatus` hook for unified sync state access
  - Created `SyncStatusIndicator` component (icon/badge/full variants)
  - Added indicator to TopBar for global visibility
  - Enhanced POS scanner to auto-cache items when scanned online
  - Improved offline scan fallback with better error messages

### 4. Vendor Analysis Unclear ✅ COMPLETED (Moved to Sales Hub)
- **Issue**: "Vendor" concept ambiguous (supplier vs customer?)
- **Current**: Treats as supplier for COGS in Finances page
- **Decision Made**: Vendor = supplier (wholesaler). Moved vendor analysis to Sales page as analytics hub.
- **Resolution**: 
  - Created `VendorPerformance` component with profit margin analysis
  - Created `CategoryPerformance` component for category-wise breakdown
  - Created `SaleTypeAnalysis` component for festival/clearance/promotion tracking
  - Restructured Sales page as "Sales Hub" with 3 tabs:
    - **Transactions**: Existing sales list with filters and pagination
    - **Analytics**: Category and sale type performance charts
    - **Vendors**: Vendor-wise sales, revenue, and margin analysis
  - Components are modular with consistent props (shopId, startDate, endDate)
